## Permission Set Groupの割り当て

ロールごとにパッケージのグループを1つ割り当てます。

| ロール | Setupのグループ名 | API名 | 含まれるPermission Sets |
| --- | --- | --- | --- |
| ユーザー | **DQS User Access** | `DQS_User_Group` | `dqs_user` |
| 管理者 | **DQS Administrator Access** | `DQS_Admin_Group` | `dqs_user` + `dqs_admin` |

**Setup → Permission Set Groups** でグループを開き、**Manage Assignments → Add Assignments** からユーザーを選び、割り当てを完了します。管理者グループには基本アクセスが含まれるため、両方を割り当てる必要はありません。

既存のPermission Setの直接割り当ては引き続き有効で、自動移行は行われません。直接割り当てる場合、管理者には `dqs_user` と `dqs_admin` が必要です。`dqs_admin` だけでは完全な管理者ロールになりません。

## ロールでできること

**DQS User Accessは読み取り専用ではありません。** ユーザーはDraft定義の作成・編集、機能と項目別設定の構成、レイアウト項目のインポート、スキャンの実行、結果の確認ができます。基本Permission Setは、定義、結果、スケジュール、エラーログの主要DQSオブジェクトに作成・読み取り・編集・削除権限も付与します。アプリケーションのルールが追加の制限を適用します。

**DQS Administrator Access** はDraft定義の削除、Field Usageの設定、レポート生成、履歴閲覧、PDF出力などの管理操作を追加します。有効な定義はDQS管理者でも削除できません。

## データアクセスと有効化

分析対象のSalesforceデータにはオブジェクトと項目の権限が引き続き適用されます。DQSアクセスはすべてのソースオブジェクト、項目、メタデータへのアクセスを保証しません。Field Usage設定と保存済みレポートには管理者アクセスが必要で、基本ロールには含まれません。

グループの割り当てでパッケージは有効化されません。インストール後に別途[アプリの有効化](/ja/getting-started/installation/)を完了してください。
