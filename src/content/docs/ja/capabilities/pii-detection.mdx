## PII Detectionとは

PII Detectionは、自由テキスト項目で**本来保存されるべきでない個人を特定できる情報**をスキャンします。GDPR、CCPA、HIPAAなどのデータプライバシー規制への準拠を支援します。

## 仕組み

PII Detectionストラテジーは、以下に一致するパターンのテキストコンテンツを分析します：

1. **社会保障番号**（SSN） — XXX-XX-XXXXのような数値パターン
2. **クレジットカード番号** — カードネットワークパターンに一致する13〜19桁のシーケンス
3. **メールアドレス** — メールの保存が想定されていない項目内
4. **電話番号** — 自由テキスト項目内（専用の電話番号項目ではない）
5. **国民識別番号** — 国固有のパターン

## 構成

### 検出パターン

**Defaults**セクションでは、3つのプリセット検出パターングループを提供します：

| プリセット | 説明 |
|--------|-------------|
| **Standard** | コアPIIパターン — 社会保障番号、クレジットカード番号、メールアドレス、US電話番号 |
| **Critical** | 高リスクの金融・身元識別パターン |
| **Extended** | IPアドレス、IBAN、生年月日、国際電話番号など、完全なセット |

各パターンの正規表現が表示され、個別に有効・無効を切り替えられます。**Add Custom Pattern**セクションで正規表現とラベルを入力して独自のパターンを追加することもできます。

![PII Detectionの構成 — 検出パターンプリセット（Standard、Critical、Extended）、パターンリスト、Field Overrides](../../../../assets/screenshots/pii-generic-view.png)

### 項目ごとのオーバーライド

Field Overridesテーブルで項目をクリックすると、構成モーダルが開きます。その項目に適用する検出パターンを選択できます — プリセットを選択するか、個別のパターンを有効・無効にできます。モーダルではその項目固有の**カスタムパターン**を追加することもできます。**Revert to Global**リンクを使用してリセットできます。

![Description項目の項目ごとの構成モーダル — 検出パターンとカスタムパターン入力](../../../../assets/screenshots/pii-field-override.png)

## スコアリング

| 結果 | スコア |
|--------|-------|
| PIIが検出されない | 100 |
| 一部のPIIが発見された | クリーンな割合に比例 |
| すべてのレコードにPII | 0 |
| データなし | 0 |

<Aside type="caution">
PII Detectionはパターンマッチングを使用しており、AI分類ではありません。誤検出（例：SSNのように見えるがSSNではない番号）が発生する場合があります。アクションを実行する前に、フラグされたレコードをレビューしてください。
</Aside>

## PII正規表現パターン

DQSは自由テキスト項目でPIIを検出するために**Java互換の正規表現**を使用します。インタラクティブなテスターと完全なPIIパターンライブラリ（SSN、クレジットカード（Visa、Mastercard、Amex）、IBAN、パスポート番号、PESEL、NIPなど）については、[正規表現テスター](/ja/reference/regex-tester/)をご覧ください。

## ユースケース

- DescriptionやNotes項目に誤って保存されたクレジットカード番号を監査
- 自由テキスト項目の社会保障番号を監視
- データプライバシー規制のコンプライアンスレポート
- マイグレーション前のデータクレンジング
