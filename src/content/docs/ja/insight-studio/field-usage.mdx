## Field Usageで確認できること

Field Usageは、選択した項目への参照をSalesforceメタデータから検索します。対象は依存関係、Apexクラスとトリガー、レイアウト、レポートです。アクセス権を示す **Access grants** は別に表示されます。項目の設定を変更する前に、参照元を調べるために使用します。

設定、生成、保存済みレポートの閲覧、PDF出力には **DQS Administrator** アクセスが必要です。この任意のメタデータ分析は、品質スコアやスキャンのスケジュールを変更しません。

## Builderでレポートを有効にする

1. [Builder](/ja/builder/overview/)で定義を開き、**Scope** の項目を保存します。
2. **Configure** の後、**Review** の前にある **Field Usage (optional)** を開きます。
3. **Enable Field Usage reports** をオンにします。新規・既存の定義ともに初期状態では無効です。オンにすると、保存済みScope内のアクセス可能な項目がすべて選択されます。分析しない項目の選択を解除してください。
4. 項目ラベルまたはAPI名で検索できます。**Select all**（画像では **Select all matching fields** と表示） は現在の検索結果やページ以外も含め、利用可能なScope全体を選択します。**Clear selection** は選択を解除します。1ページに25項目が表示されます。
5. 少なくとも1項目を選択し、次に進む前にBuilderのヘッダーで **Save** をクリックします。

有効な設定を再度開くと、保存済みの選択が維持されます。後からScopeに追加した項目は自動選択されません。削除された項目やアクセスできない項目は新しいレポートから除外されます。アクセス可能な項目がない場合は、まずScopeに項目を保存するか、Field Usageを無効のままにします。

![Field Usageを有効にし、25項目すべてを選択した保存前の状態](../../../../assets/screenshots/field-usage-builder-setup.png)

Field Usageを無効にしたまま定義を完了できます。Configureの **Confirm Configuration** はケイパビリティ設定を確定し、**Continue** はField Usageへ進みます。必須設定が完了し、Field Usageの変更が保存されると、Field UsageとReviewで **Mark as Complete** が使用できます。

## レポートを実行する

1. Insight Studioでオブジェクトまたは定義の **Field Usage** を開きます。オブジェクトビューでは、先に定義を選択します。
2. **Current definition scope** を展開し、次のレポートの対象項目を確認します。
3. **Run Field Usage Report**（レポートが開いている場合は **Run Report Again**）をクリックします。アプリは最新の保存済み設定を確認し、その選択を分析します。タブを開くだけでは保存済みレポートが読み込まれます。

ソースの確認中に結果が順次表示されます。**Stop** は分析を終了し、それまでの結果をStoppedステータスで保存します。ビューを離れると分析は停止しますが、実行中のレポートは自動保存されません。

![Stopとソースの確認状況を表示する実行中のField Usage分析](../../../../assets/screenshots/field-usage-running.png)

## 結果を読む

- **Usage by field** はDependencies、Apex、Layouts、Reports, Needs review、Access grantsの件数を1ページ8項目で表示します。項目または件数をクリックすると詳細を絞り込めます。
- **Details** はField、Source、Component、Evidenceを表示し、検索、ソースフィルター、1ページ15行のページ分割を備えています。**All references** は重複を除いた確認済みのコンポーネントと項目の組み合わせです。**Needs review** は不確かな一致、**Access grants** は権限を示し、どちらも確認済み参照の合計には含まれません。
- **0** はソースを確認した結果、参照が見つからなかったことを示します。**—** は確認範囲が不完全で、まだ一致が収集されていないことを示します。件数が正でもソースの確認状況を確認してください。
- Apex/SOQL分析はオブジェクトと項目の文脈を確認し、コメント、ラベル文字列、識別できた他オブジェクトへの参照を除外します。テストコードの参照は画面に表示されず、合計にも含まれません。旧レポートの **Text match** は **Needs review** として扱います。権限はアクセスの証拠であり、使用の証拠ではありません。同じコンポーネントが複数のソースに含まれるため、ソース別件数は足し合わせないでください。

![参照数、アクセス権、詳細を表示するCaseの保存済みField Usageレポート](../../../../assets/screenshots/field-usage-report.png)

## 保存済みレポート

完了したレポートとStopで明示的に停止したレポートは自動保存されます。戻ると最新の保存済みレポートが開き、**Saved reports** から定義の最新50件を選択できます。履歴を開いても分析は再実行されません。各レポートは現在の定義の対象項目とは別に、元の項目と生成日時を保持します。

BuilderでField Usageを無効にすると新規レポートは作成できなくなりますが、保存済みレポートは閲覧できます。保存に失敗しても結果は表示されたままで、**Retry Save** で分析を繰り返さずに再保存できます。JSONが500,000文字を超えるレポートは表示されますが保存されません。項目数を減らして新しいレポートを実行してください。

![Field Usageを無効にしても閲覧できるOpportunityの保存済みレポート](../../../../assets/screenshots/field-usage-history.png)

## 手動スキャン後の自動レポート

管理者がDQSアプリからスキャン（**Complete & Run Scan** を含む）を開始すると、品質スキャンのキュー登録が成功した後、定義のレポートが有効な場合にField Usageダイアログが自動で開きます。分析が終了するまで開いたままにするか、**Stop** で途中結果を保存してください。品質スキャンは別にバックグラウンドで続行します。スケジュール実行ではField Usageレポートは生成されません。メタデータ分析には開いたブラウザセッションが必要です。

## 参照先を開く

対応するコンポーネント名をクリックすると、同じSalesforce組織のApexクラス/トリガー、ページレイアウト、Flowバージョン、Permission Set、プロファイル、レポートが開きます。未対応の参照先はテキストのままです。Salesforceのアクセス確認は引き続き適用されます。古いレポートのリンク、特に権限の付与元のリンクを補うには再実行が必要な場合があります。

## PDFのダウンロード

保存済みレポートを開き、分析と保存の完了後に **Download PDF** をクリックします。DQSのデザインを使用したPDFは、使用状況レポートに関連付けたSalesforce Fileとして保存され、保存時の対象範囲、日時、カバレッジ、件数、証拠、対応リンクを含みます。再分析や品質違反のエクスポートは行いません。不確かな証拠やテストの証拠が明示的なラベル付きでPDF詳細に含まれる場合も、確認済み参照の合計からは除外されます。

## カバレッジの制限

Field Usageはメタデータ参照を示すもので、実行時の活動記録や安全に項目を削除できる保証ではありません。依存関係の検索は現在カスタム項目の識別子を使用するため、Flowや入力規則内の標準項目の使用を検出できない場合があります。動的Apex/SOQL、未解決の型、アクセスできないメタデータ、未対応の構文もカバレッジを制限します。変更前に **Needs review** とソースのカバレッジを確認してください。確認済み参照がゼロでも未使用とは限りません。

このページの画像は旧レイアウトです。現在は **Needs review**、コンポーネントへのリンク、**Download PDF** も含まれます。
