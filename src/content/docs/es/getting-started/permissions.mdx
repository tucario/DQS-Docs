## Asignar un Permission Set Group

Asigne un grupo incluido en el paquete para cada rol:

| Rol | Grupo en Setup | Nombre API | Permission Sets incluidos |
| --- | --- | --- | --- |
| Usuario | **DQS User Access** | `DQS_User_Group` | `dqs_user` |
| Administrador | **DQS Administrator Access** | `DQS_Admin_Group` | `dqs_user` + `dqs_admin` |

En **Setup → Permission Set Groups**, abra el grupo, seleccione **Manage Assignments → Add Assignments**, elija usuarios y complete la asignación. El grupo administrador incluye el acceso base; no necesita asignar ambos grupos.

Las asignaciones directas existentes siguen siendo válidas y no se migran automáticamente. Con asignación directa, los administradores necesitan `dqs_user` y `dqs_admin`; `dqs_admin` por sí solo no proporciona el rol completo.

## Capacidades de cada rol

**DQS User Access no es de solo lectura.** Los usuarios pueden crear y editar definiciones Draft, configurar capacidades y ajustes por campo, importar campos de diseños, ejecutar escaneos y consultar resultados. El Permission Set base también permite crear, leer, editar y eliminar registros de los objetos principales DQS de definiciones, resultados, programaciones y errores. Las reglas de la aplicación añaden restricciones.

**DQS Administrator Access** añade operaciones administrativas, incluida la eliminación de definiciones Draft y la configuración, generación, historial y exportación PDF de Field Usage. Ni siquiera un administrador DQS puede eliminar definiciones activas.

## Acceso a datos y activación

Los permisos de objetos y campos siguen aplicándose a los datos Salesforce analizados. El acceso DQS no garantiza acceso a todos los objetos fuente, campos o metadatos. Los ajustes Field Usage y los informes guardados requieren acceso administrador y no forman parte del rol base.

Asignar un grupo no activa el paquete. Complete la [activación de la aplicación](/es/getting-started/installation/) por separado tras la instalación.
