## تعيين Permission Set Group

عيّن مجموعة واحدة من الحزمة لكل دور:

| الدور | المجموعة في Setup | اسم API | Permission Sets المضمّنة |
| --- | --- | --- | --- |
| مستخدم | **DQS User Access** | `DQS_User_Group` | `dqs_user` |
| مسؤول | **DQS Administrator Access** | `DQS_Admin_Group` | `dqs_user` + `dqs_admin` |

في **Setup → Permission Set Groups** افتح المجموعة واختر **Manage Assignments → Add Assignments**، ثم حدد المستخدمين وأكمل التعيين. تتضمن مجموعة المسؤول الوصول الأساسي؛ لا يلزم تعيين المجموعتين.

تظل تعيينات Permission Sets المباشرة الحالية صالحة ولا تُرحّل تلقائيًا. عند التعيين المباشر، يحتاج المسؤول إلى `dqs_user` و`dqs_admin` معًا؛ لا يوفر `dqs_admin` وحده دور المسؤول الكامل.

## إمكانات الأدوار

**DQS User Access ليس دورًا للقراءة فقط.** يستطيع المستخدم إنشاء تعريفات Draft وتعديلها وتكوين القدرات وإعدادات الحقول واستيراد حقول التخطيطات وتشغيل الفحوص وقراءة النتائج. يمنح Permission Set الأساسي أيضًا صلاحيات الإنشاء والقراءة والتعديل والحذف على كائنات DQS الرئيسية للتعريفات والنتائج والجداول وسجلات الأخطاء. تفرض قواعد التطبيق قيودًا إضافية.

يضيف **DQS Administrator Access** عمليات إدارية، منها حذف تعريفات Draft وإعداد Field Usage وإنشاء تقاريره وقراءة سجله وتصدير PDF. لا يستطيع مسؤول DQS أيضًا حذف التعريفات النشطة.

## الوصول إلى البيانات والتفعيل

تظل صلاحيات الكائنات والحقول سارية على بيانات Salesforce التي تُحلل. لا يضمن الوصول إلى DQS الوصول إلى كل كائنات المصدر أو الحقول أو البيانات الوصفية. تتطلب إعدادات Field Usage وتقاريره المحفوظة وصول المسؤول، ولا تدخل في الدور الأساسي.

تعيين المجموعة لا يفعّل الحزمة. أكمل [تفعيل التطبيق](/ar/getting-started/installation/) بصورة منفصلة بعد التثبيت.
