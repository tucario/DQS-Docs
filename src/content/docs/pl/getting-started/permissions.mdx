## Przypisywanie grupy uprawnień

Przypisz jedną grupę z pakietu dla danej roli:

| Rola | Grupa w Setup | Nazwa API | Zawarte zestawy uprawnień |
| --- | --- | --- | --- |
| Użytkownik | **DQS User Access** | `DQS_User_Group` | `dqs_user` |
| Administrator | **DQS Administrator Access** | `DQS_Admin_Group` | `dqs_user` + `dqs_admin` |

W **Setup → Permission Set Groups** otwórz grupę, wybierz **Manage Assignments → Add Assignments**, zaznacz użytkowników i zakończ przypisanie. Grupa administratora zawiera już dostęp podstawowy; nie trzeba przypisywać obu grup.

Dotychczasowe bezpośrednie przypisania permission sets pozostają ważne i nie są automatycznie migrowane. Przy przypisywaniu bezpośrednim administrator potrzebuje `dqs_user` oraz `dqs_admin`; samo `dqs_admin` nie zapewnia kompletnego dostępu administratora.

## Zakres ról

**DQS User Access nie jest rolą tylko do odczytu.** Użytkownik może tworzyć i edytować definicje Draft, konfigurować zdolności i ustawienia pól, importować pola z layoutu, uruchamiać skany i przeglądać wyniki. Podstawowy permission set przyznaje także tworzenie, odczyt, edycję i usuwanie dla głównych obiektów DQS: definicji, wyników, harmonogramów i logów błędów. Reguły aplikacji nakładają dodatkowe ograniczenia.

**DQS Administrator Access** dodaje operacje administracyjne, w tym usuwanie definicji Draft oraz konfigurację Field Usage, generowanie raportów, historię i eksport PDF. Definicji aktywnych nie może usuwać również administrator DQS.

## Dostęp do danych i aktywacja

Uprawnienia do obiektów i pól nadal obowiązują dla analizowanych danych Salesforce. Dostęp do DQS nie gwarantuje dostępu do wszystkich obiektów źródłowych, pól i metadanych. Ustawienia Field Usage i zapisane raporty wymagają roli administratora; nie są częścią roli podstawowej.

Przypisanie grupy nie aktywuje pakietu. Po instalacji wykonaj osobno [aktywację aplikacji](/pl/getting-started/installation/).
