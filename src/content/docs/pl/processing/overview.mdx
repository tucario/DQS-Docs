## Jak działają skany

Silnik przetwarzania to **warstwa wykonawcza** Data Quality Sense. Odczytuje definicje skanów utworzone w Builder, odpytuje bieżące dane Salesforce i generuje wyniki jakości widoczne w Insight Studio.

## Architektura

```
Definition + Details
       │
       ▼
  Batch Job Start
       │
       ▼
  Query target SObject (dynamic SOQL)
       │
       ▼
  For each enabled dimension:
    Strategy.processChunk(context)
       │
       ▼
  Aggregate partial results
       │
       ▼
  Store: Dimension Results → Field Results → Metric Results
       │
       ▼
  Fire platform event: Calculation Complete
```

## Kluczowe pojęcia

| Pojęcie | Opis |
|---------|------|
| **Skan** | Pojedyncze uruchomienie definicji na bieżących danych |
| **Strategia wymiaru** | Jedna klasa strategii na zdolność (np. CompletenessStrategy) |
| **Przetwarzanie fragmentów** | Rekordy przetwarzane wsadowo za pomocą `Database.Batchable` |
| **Obliczanie metryk** | Metryki per pole obliczane w ramach każdej strategii |
| **Przechowywanie wyników** | Hierarchiczne: Dimension → Field → Metric results |
| **Platform Events** | `Calculation_Complete__e` uruchamiany po zakończeniu skanu |

## Wyzwalanie skanu

Skany mogą być wyzwalane na trzy sposoby:

1. **Ręcznie** — Kliknij „Run Scan" w Insight Studio
2. **Zaplanowane** — Przez [harmonogramowanie](/pl/processing/scheduling/) oparte na CRON
3. **Programowo** — Przez Apex API (do niestandardowych integracji)

## Hierarchia wyników

```
DQS_Dimension_Result__c  (jeden per wymiar per skan)
  └── DQS_Field_Result__c  (jeden per pole per wymiar)
       └── DQS_Metric_Result__c  (szczegółowe metryki per pole)
```
